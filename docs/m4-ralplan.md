## Pre-mortem

<!-- revision 1: change #30 — expanded from 2 scenarios to 5, each with file-specific mitigation -->

Five scenarios most likely to derail M4. Each has a concrete, location-specific mitigation.

### (a) SSE listener memory leak

**Risk:** A client disconnects but the `eventBus` listener is never removed, causing the listener list to grow unboundedly and eventually crashing the process.

**Where it would manifest:** `apps/ledger/src/http/events.js` and `apps/identity/src/http/events.js` — the `request.raw.on('close', ...)` handler.

**Mitigation:**
- A single `close` handler (not two separate registrations) must call both `eventBus.off('event', send)` and `clearInterval(keepalive)`.
- Done criterion: `eventBus.listenerCount('event')` returns to baseline after each disconnect.
- Observability: emit a structured log `{ event: 'sse_client_disconnected', listenerCount: eventBus.listenerCount('event') }` on close so the cleanup is verifiable in logs.

### (b) Playwright SSE flakiness

**Risk:** SSE assertions using `waitForSelector` on `data-testid="terminal-line"` or `data-testid="service-state-ledger"` time out intermittently because elements render asynchronously after the SSE connection is established and an HTTP request completes.

**Where it would manifest:** `apps/web/tests/observability.spec.ts` (PR 7).

**Mitigation:**
- All SSE state assertions must use `page.waitForFunction(() => ..., { timeout: 10000 })`, not `waitForSelector`.
- The done criterion for PR 7 is 3 consecutive CI-style runs passing (not a single green run).

### (c) Cross-tenant event leak from missing per-user filter

**Risk:** Without a per-user filter in the `send` function, every connected SSE client receives events from every user's transactions. A user with an open stream sees another user's `db` and `idempotency_check` events — a data leak.

**Where it would manifest:** `apps/ledger/src/http/events.js` and `apps/identity/src/http/events.js` — the `send` callback registered on `eventBus`.

**Mitigation:**
- `send` must guard: `if (event.userId !== request.user.sub) return;`
- Integration test requirement: two tokens (two distinct users), two open streams; trigger a transaction on user A; assert user B's stream receives no events.
- `deriveServiceState` in `apps/web/src/modes/Observability.tsx` also filters defensively on `e.userId === currentUserId`.

### (d) Clock skew breaks graph decay window

**Risk:** If the backend server clock differs from the client clock by more than 2 seconds, the `age = Date.now() - event.timestamp` calculation will incorrectly keep services in `active` state permanently (if the backend clock is ahead) or snap to `idle` immediately (if the backend clock is behind).

**Where it would manifest:** `deriveServiceState` in `apps/web/src/modes/Observability.tsx` (PR 4).

**Mitigation:**
- Use `receivedAt` (stamped by the client in the `onmessage` handler) for decay, not `event.timestamp`.
- `event.timestamp` is preserved for terminal line rendering only.
- Done criterion: inject an event with `timestamp` set 10 seconds in the past; state must still transition to `idle` exactly 2s after `receivedAt`.

### (e) JWT rotation silently terminates stream

**Risk:** If the user's token is rotated (re-login, session expiry), the existing EventSource connection becomes permanently disconnected. EventSource auto-reconnect re-sends the same (now expired) query param, causing a permanent 401 loop that looks like a network dropout — no visible error message.

**Where it would manifest:** `apps/web/src/modes/Observability.tsx` — the `src.onerror` handler (PR 3), and `apps/{ledger,identity}/src/http/events.js` — the auth check on `?token=`.

**Mitigation:**
- On `onerror` with no prior `onopen` (i.e. `sseStatus !== 'connected'`), set state to `'auth-error'` and render a visible "Authentication failed — please sign in again" message (`data-testid="sse-auth-error"`), distinct from the "disconnected" (reconnecting) state.
- Do not silently retry on auth failure. The stream must stay closed until the user takes an explicit action.
- Document in D06: "Token rotation terminates the SSE stream; client must reconnect with a new token (no silent re-auth)."

## Key implementation notes

- `apps/{ledger,identity}` are JavaScript ESM (`"type": "module"` in `package.json`). All new backend files use `import`/`export`, no TypeScript annotations.
- Zod is already a dependency of `apps/ledger` (see `package.json`). Use it for input validation in use-cases.
- `request.user.sub` is the authenticated user identifier — not `req.user.id`.
- `src/application/usecases/` is the correct path for use-cases (not `src/use-cases/` or `src/usecases/`).
- `reply.addHook` does not exist on Fastify reply objects — use `request.server.addHook` with a per-request guard.
- The `.gitignore` malformed entry (`.claude/apps/web/test-results/`) must be split into three lines before any developer tooling state leaks into git.
